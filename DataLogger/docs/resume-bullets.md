## 通用版（4 条）

**DataLogger — 高可靠嵌入式温度记录仪** | STM32F103 + FreeRTOS | 2026.05 – 2026.10

- 设计 **16 字节定长记录格式 + 逐条 CRC16**，60 秒采样可存 **90 天**数据；
  启动时扫描有效前缀修复被复位打断的文件元数据，覆盖"数据已写、元数据未提交"窗口
- 实现 **COBS 分帧 + CRC16 + 序号停等重传**的串口协议，PC 端 `verify` 做
  端到端 CRC32 比对；**60% 随机丢帧下仍能完整还原**数据
- 实现 **报警状态机**（上下限 + 回差 + 最短持续时间）与 **MKT 平均动力学温度**，
  报警事件独立落盘，PC 端生成含 SVG 曲线的运输报告
- 在 20 KB SRAM 下完成全部功能（ROM 55224 B / 84.3%，RAM 18760 B / 91.6%），
  Keil 0 Error / 0 Warning

## 可靠性方向（工控 / 汽车电子）

- 针对 Flash 非原子写入，设计**记录级 CRC + 启动逐条扫描恢复**，
  异常复位后自动修复文件元数据
- 配置采用 **A/B 双区 + 版本号 + CRC**，先写 B 验证再写 A，覆盖全部四类断电窗口
- **故障诊断隔离**：栈溢出/堆失败钩子只写 volatile 与 BKP 备份寄存器，
  不调用 UART/队列/互斥量，避免二次故障掩盖根因；故障码跨复位保留
- 驱动层主动修正：Flash 驱动原先无条件返回 `HAL_OK`，改为透传 HAL 状态，
  BUSY 超时返回 `HAL_TIMEOUT`，让上层错误处理真正生效

## 低功耗 / IoT 方向

- **tickless + STOP 模式**：自定义 `vPortSuppressTicksAndSleep`，
  用 PCF8563 秒差补 tick，按键改 EXTI 唤醒消除 50 ms 轮询
- 外设门控：OLED 关电荷泵（8 mA → 10 µA）、W25Q64 深睡（4 mA → 1 µA）、
  OLED 事件驱动刷新
- 建立**功耗预算模型**（`tools/power_budget.py`）：干净配置 **54 µA**，
  原版 Blue Pill 7.05 mA；明确指出差距来自板级固定开销（LED 2 mA + AMS1117 4 mA）

## 面试可讲的技术判断

1. **为什么记录级用 CRC16 而文件级用 CRC32**
   16 字节记录里 CRC32 占 25%；记录短，CRC16 漏检率已远低于 Flash 位翻转概率。
   文件级仍需 CRC32 做导出时的端到端比对。

2. **为什么不用 LittleFS**
   目标是理解页编程/扇区擦除/非原子写入；自实现过程中遇到了索引整扇区擦写
   导致 40% 断电窗口丢失元数据的问题，这个认识是选用成熟方案的依据。

3. **为什么按键要拆成"EXTI 唤醒 + 任务内消抖"**
   中断里做 30 ms 消抖会阻塞系统；纯轮询在低功耗下每 50 ms 醒一次，
   占空比 4% × 15 mA ≈ 600 µA，比整个 60 s 档预算还高。

4. **为什么睡眠前必须先门控器件再关中断**
   `HAL_Delay` 与 HAL 超时依赖 SysTick。关中断期间 tick 冻结，
   任何依赖超时的调用会永久阻塞——这是实机调试中遇到并修正的问题。
