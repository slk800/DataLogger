# 硬件清单与接线

> 目标：在**不焊接**的前提下，把 DataLogger 从"能跑"升级到"能导出 + 能长期部署"。
> 全部连接使用面包板 + 杜邦线。

### 为什么选 PCF8563 而不是 DS3231

| | PCF8563 | DS3231 |
|---|---:|---:|
| 计时电流 | **0.25 µA** | 110–200 µA |
| 秒级 alarm | ❌（只有分/时/日） | ✅ |
| 1 Hz 输出 | ✅ CLKOUT | ✅ SQW |
| 影响 | 可忽略 | **吃掉整个 60 s 档预算**（54 µA） |

DS3231 精度更高（±0.3 s/90 天 vs ±2.6 min/90 天），但 110 µA 的静态电流
会让低功耗改造失去意义。如果后续需要高精度，可以加装但**必须能断电**。

## 3. 接线图

### 3.1 基础（已有）

```
Blue Pill
  PA0  ────  NTC #1 AO
  PB6  ────  OLED SCL
  PB7  ────  OLED SDA
  PB0  ────  W25Q64 CS
  PA5  ────  W25Q64 SCK
  PA6  ────  W25Q64 MISO
  PA7  ────  W25Q64 MOSI
  PB12 ────  KEY UP   （按下接 GND）
  PB13 ────  KEY DOWN
  PB14 ────  KEY OK
  PA9  ────  USART1 TX
  PA10 ────  USART1 RX
  PA13/PA14 ── SWDIO / SWCLK
```

### 3.2 新增（W2 / W3）

```
PCF8563 模块                Blue Pill
  VCC     ────────────────  3.3V
  GND     ────────────────  GND
  SDA     ────────────────  PB7      （与 OLED 共用 I2C1）
  SCL     ────────────────  PB6
  CLKOUT  ────────────────  PB1      （EXTI1，低功耗唤醒）
  INT     ────────────────  不接

NTC 模块 #2
  VCC     ────────────────  3.3V
  GND     ────────────────  GND
  AO      ────────────────  PA1      （ADC1_IN1）
  DO      ────────────────  不接

CH340 USB-TTL
  TX      ────────────────  PA10     （CH340 的 TX 接 MCU 的 RX）
  RX      ────────────────  PA9
  GND     ────────────────  GND
  VCC     ────────────────  不接      （防止倒灌，测功耗时必须拔）
```

### 3.3 I2C 地址

| 器件 | 7 位地址 | 说明 |
|---|---|---|
| SSD1306 | `0x3C` | OLED |
| PCF8563 | `0x51` | RTC |

两者不冲突，可共用 PB6/PB7。模块通常自带 4.7 kΩ 上拉，并联后仍可用 100 kHz。

### 3.4 功耗测量（可选）

```
电池盒 +  ────  HT7333 IN
HT7333 OUT ──  INA219 VIN+
INA219 VIN- ──  Blue Pill 3V3
所有 GND 共地

INA219 的 VCC 接 5V 侧（不要接 3.3V 轨）
测量时拔掉 USB 与 ST-Link
```

> INA219 自身耗电约 1 mA。若从被测量的 3.3 V 轨取电，测到的是"板子 + 表"。

## 4. CubeMX 需要改的地方

接第二路 NTC 时，PA1 需要配置为模拟输入并加入 ADC 扫描：

1. 打开 `DataLogger.ioc`
2. `ADC1` → `IN1` 勾选
3. `ScanConvMode` 改为 `Enabled`，`NbrOfConversion` 改为 `2`
4. `Rank 1 = Channel 0`，`Rank 2 = Channel 1`
5. 重新生成代码（**注意不要覆盖 `App/`、`BSP/` 里的 USER CODE 段**）

> 当前 `sensor_ntc.c` 只读通道 0。第二通道需要在
> `Sensor_NTC_Read` 之后追加一次 `ADC_CHANNEL_1` 的读取，
> 并填入 `RecordV2_t.t2_x100`。

## 5. 分阶段联调顺序

| 阶段 | 接线 | 验证命令 | 期望 |
|---|---|---|---|
| 1 | 只接 PCF8563 | `dltool time` | 读到有效 UTC |
| 2 | 加 CH340 | `dltool info` | 固件版本 + 存储状态 |
| 3 | — | `dltool ls` | 列出 sample / log |
| 4 | — | `dltool verify --name sample` | CRC32 一致 |
| 5 | 加 NTC #2 + 改 CubeMX | `dltool plot sample.bin` | CSV 含两列温度 |
| 6 | 全部 + 电池 | `python tools/power_budget.py` | 与实测对照 |

**不要一次全部接上**：I2C 总线上多一个器件就多一种失败模式，
分步接入能把问题定位到具体模块。

## 6. 常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| `dltool` 无响应 | TX/RX 接反 | CH340 TX → PA10，RX → PA9 |
| I2C 扫描不到 0x51 | 未共地 / 未上拉 | 检查 GND，模块自带 4.7k |
| 时钟读出 2000-00-00 | VL 位为 1（掉电） | `dltool time --set now` |
| STOP 后不醒 | CLKOUT 未接或未使能 | 检查 PB1 接线，`BSP_RTC_SetClkout(1)` |
| 测到 7 mA 降不下来 | 板载 LED + AMS1117 | 这是板级地板，见 [power.md](power.md) |
| 编译报 `FILE_TYPE_EVENTS` 未定义 | FS 版本不匹配 | 确认在 `w2-w3` 分支 |
